## Priority Issues

### [P0] Панель фильтров перекрыта вкладками менеджеров

`.dc-daily-manager-integrated` (имя, поиск, три фильтра) — `position: absolute; bottom: calc(100% + 14px); left/right: 0; z-index: 4` внутри `.dc-daily-list { overflow: hidden }`. Панель выходит на 135px выше списка (top 228 против 363) под ряд вкладок. Живой hit-test: «Красные · 21» (y 283) перехватывается `STRONG` вкладки; «Жёлтые · 5» (283) — `STRONG`; «Зелёные · 0» (283) — `STRONG`; поиск (323) — `.dc-daily-manager-status`. Ни один не кликабелен. Причина: `.dc-daily-managers { position: relative; z-index: 1 }` перекрывает `z-index: 4`, так как лежит позже в потоке. РОП не может ни отфильтровать очередь, ни найти сделку; три «кнопки» выглядят живыми, но нажимают вкладку. Фикс: вывести шапку в поток первым `flex: 0 0 auto` рядом внутри `.dc-daily-list`, убрать абсолютное позиционирование, сварку оставить геометрией; альтернатива — `.dc-daily-list { overflow: visible }` с переносом радиусного клиппинга во внутреннюю обёртку. Команда: $impeccable harden.

### [P0] У отметки «Проверено РОПом» нет состояния завершения

`.dc-daily-deal.reviewed` рендерится в className (DailyControl.tsx:786) и не имеет ни одного CSS-правила. `reviewedDealIds` нигде не выводится как счётчик. `toggleReviewed` оптимистично уводит сделку в конец и сразу подменяет правую панель: ни тоста, ни `role="status"`, ни `aria-live`. Отметка проверенным — единственное высокорисковое действие, и оно не даёт обратной связи: РОП не знает, записалось ли, сколько из скольких разобрано, и что панель сменилась под ним. Для продукта с обещанием «AI готовит утреннюю планёрку» у разбора нет конца — peak-end failure в реальном продукте. Фикс: (1) стилизовать `.reviewed` (opacity ~.62, `line-through` на `strong`, чип «Проверено» в `--daily-green`); (2) `Разобрано 7 из 24` в `.dc-daily-team-head` с полосой прогресса; (3) `aria-live="polite"` на автопереход; (4) inline-карточка «Разбор завершён» когда все сделки менеджера разобраны. Команда: $impeccable overdrive.

### [P1] Две палитры статусов, точки в списке не проходят AA

Светофор и счётчики используют `--daily-red #c9323e` / `--daily-yellow #956000` / `--daily-green #067647`; `DealStatusIndicator` рисует `--dc-red #df4040` / `--dc-orange #e99000` / `--dc-green #159454`. Контраст белого глифа: 2.48:1 / 3.89:1 / 4.25:1 — все ниже AA. «Красный» в светофоре и «красный» в списке — разные оттенки, и самый слабый в самой очереди. Фикс: `.dc-daily { --dc-red: #c9323e; --dc-orange: #956000; --dc-green: #067647; }` одной строкой. Команда: $impeccable colorize.

### [P1] `Всего сделок` считает то, чего список не покажет

`summarizeDailyControl` считает все сделки в `deals_total`/`deals_count`, а `dealMatchesDailyTrafficStatus` возвращает `false` для `neutral`. Шапка говорит «Всего сделок 120», карточка «12 сделок», список показывает максимум red+yellow+green. `Без движения` при `movementScope === 0` тихо даёт «0 из 120», что может означать «нет данных». Это два числа, которые РОП произносит вслух. Фикс: исключить `neutral` и добавить «N без статуса», либо «12 в разборе · 108 без статуса»; при `movementScope === 0` рендерить `—` со сноской. Команда: $impeccable clarify.

### [P2] Сценарий планёрки filed как сноска, вопрос — 13px чекбокс

Порядок правой панели: ситуация → 3 критерия качества → коммуникации (6 ячеек + свёртка) → блок с вопросами → две свёрнутые плитки, включая «Готовый сценарий разговора». Продукт существует ради сценария и вопроса; они за шевроном, а выше — три AI-оценки с наведением. Фикс: поднять вопрос в первый блок, `direct_question` 17px/700, сценарий в постоянный блок, качество опустить под свёртку. Команда: $impeccable bolder.
